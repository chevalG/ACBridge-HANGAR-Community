# ACBridge HANGAR 3.1.3 · 双语界面实现说明 / i18n implementation notes

本文件面向维护者，说明 3.1.3 双语机制的边界与扩展方式。

## 机制概览 / Overview

- **前端**：`web/js/i18n.js` 提供 `t(key, params)`、`registerStrings(ns, dict)`、
  `applyDOM(root)`、`lang()`、`setLang()`、`onChange()`。每个模块的文字典放在
  `web/js/strings-<module>.js`（`zh-CN` + `en` 两个键集，键数一致）。静态 HTML
  用 `data-i18n` / `data-i18n-title` / `data-i18n-placeholder` / `data-i18n-aria`
  属性；切换语言时 `app.js refreshForLanguage()` 重新应用静态文案并重渲染动态
  面板。
- **语言选择**：首次启动读浏览器（Windows 系统）语言，`zh*` → 简体中文，其余
  → 英文；手动选择持久化在 `localStorage('hangar_ui_lang')`。
- **后端**：`hangar/i18n.py` 提供同名机制（`register` + `t`）。HTTP 层从每个请
  求的 `X-Hangar-Lang` 头读取语言（`hangar/server.py`），作业线程在提交时捕获
  提交端语言（`hangar/jobs.py`）。无头的调用（测试、curl）保持 `zh-CN`，与历史
  行为一致。`launch.py` 与桌面壳 `HANGAR.exe` 跟随 Windows 显示语言。
- **错误摘要**：前端对稳定错误码（`err.*` 字典）给出本地化摘要；服务端原始消
  息保留在 `err.originalMessage` 与「技术诊断」折叠区。

## 数据红线 / Data boundaries

以下内容永远不做翻译，也不会被语言切换改写：

- 部件 ID、动作 ID、武器与敌方资源代号、文件路径、sha256、Entity/NPC 编号；
- `library.py NAMES` 与馆藏索引中的组合显示名（如 `IB-07: SOL 644 · 艾尔`）；
- `identity_defaults.json` 等身份数据（展示层仅在记录同时含 `names.zh` /
  `names.en` 时按语言取用，不写回、不改写）；
- 内嵌研究数据 JSON（`h14-coverage.html` 的 reason 记录等）；
- 用户编辑的名称、别名与备注。

## 已知边界 / Known boundaries

- 实验性 FXR 研究视图（`fxr-*.js`、`source-*.js`）与未从界面链接的研究页
  （`h12-coverage.html`、`h23-motion-coverage.html`）保持中文。这些面板在常规
  构建中被特性开关隐藏，不属于普通用户可达界面。
- 作业记录里已保存的历史消息按产生时的语言存储；切换语言后旧消息不回溯翻
  译，新作业按当前语言输出。
- `h16-strider.html` 与 `h14-coverage.html` 两个独立页面在页面内提供独立的语
  言按钮（切换后整页刷新）。

## 新增文案 / Adding strings

1. 在对应模块的 `strings-<module>.js` 里同时添加 `zh-CN` 与 `en` 键（保持键数
   一致）；`zh` 文案是面向用户的原文，`en` 必须忠实保留「未验证 / 部分支持 /
   近似」等限定词，不得夸大能力。
2. 静态 HTML 使用 `data-i18n` 系列属性；混合内容（按钮内含 SVG）把文字包进
   `<span data-i18n>`。
3. 新增后端消息用 `i18n.register('<ns>', {...})` + `i18n.t('<ns>.key')`；插值
   用命名参数 `{name}`，模板里避免出现字面花括号。
